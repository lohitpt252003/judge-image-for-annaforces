\section*{Project Overview}
This project is a simple and robust code execution engine built with Flask and Docker. It provides a secure environment to execute code in different languages with resource constraints (time and memory limits).

\section*{Features}
\begin{itemize}
    \item \textbf{Secure Execution:} Code is executed in an isolated Docker container to prevent any harm to the host system.
    \item \textbf{Language Support:} Supports C, C++, and Python.
    \item \textbf{Resource Limits:} Enforces time and memory limits on code execution.
    \item \textbf{Custom Output Validation:} Supports custom validator scripts to check the correctness of the user's output.
    \item \textbf{Comprehensive Test Suite:} Includes unit and API tests to ensure reliability.
\end{itemize}

\section*{API Endpoint}

\subsection*{`/api/execute`}
This is the main endpoint to submit code for execution.
\begin{itemize}
    \item \textbf{Method:} `POST`
    \item \textbf{Content-Type:} `application/json`
\end{itemize}

\subsubsection*{Request Payload}
\begin{tabularx}{\textwidth}{|l|l|l|X|}
    \hline
    \textbf{Field} & \textbf{Type} & \textbf{Required} & \textbf{Description} \\
    \hline
    `language` & string & Yes & The programming language (`c`, `c++`, `python`). \\
    \hline
    `code` & string & Yes & The source code to execute. \\
    \hline
    `stdin` & string & No & Standard input for the code. Defaults to empty. \\
    \hline
    `timelimit` & integer & No & Time limit in seconds. Defaults to 2. \\
    \hline
    `memorylimit` & integer & No & Memory limit in megabytes. Defaults to 1024. \\
    \hline
\end{tabularx}

\paragraph{Example Request:}
\begin{lstlisting}[language=json, caption=Example Request]
{
    "language": "python",
    "code": "print('Hello, World!')",
    "stdin": "",
    "timelimit": 5,
    "memorylimit": 128
}
\end{lstlisting}

\subsubsection*{Response Payload}
\begin{tabularx}{\textwidth}{|l|l|X|}
    \hline
    \textbf{Field} & \textbf{Type} & \textbf{Description} \\
    \hline
    `success` & boolean & `true` if the code executed successfully, `false` otherwise. \\
    \hline
    `stdout` & string & The standard output of the code. \\
    \hline
    `stderr` & string & The standard error of the code. \\
    \hline
    `err` & string & A high-level error message (e.g., "Compilation Error", "Time Limit Exceeded"). \\
    \hline
    `timetaken` & float & The time taken for the code to execute in seconds. \\
    \hline
    `memorytaken` & float & The memory consumed by the code in megabytes. \\
    \hline
\end{tabularx}

\paragraph{Example Response (Success):}
\begin{lstlisting}[language=json, caption=Example Success Response]
{
    "success": true,
    "stdout": "Hello, World!\n",
    "stderr": "",
    "err": "",
    "timetaken": 0.01,
    "memorytaken": 7.6
}
\end{lstlisting}

\subsection*{`/api/validate`}
This endpoint validates a user's output using a custom validator script.
\begin{itemize}
    \item \textbf{Method:} `POST`
    \item \textbf{Content-Type:} `application/json`
\end{itemize}

\subsubsection*{Request Payload}
\begin{tabularx}{\textwidth}{|l|l|l|X|}
    \hline
    \textbf{Field} & \textbf{Type} & \textbf{Required} & \textbf{Description} \\
    \hline
    `validator_language` & string & Yes & The language of the validator script (`python`). \\
    \hline
    `validator_code` & string & Yes & The source code of the validator script. \\
    \hline
    `user_output` & string & Yes & The `stdout` from the user's code execution. \\
    \hline
    `test_input` & string & Yes & The original `stdin` for the test case. \\
    \hline
\end{tabularx}

\paragraph{Example Request:}
\begin{lstlisting}[language=json, caption=Example Validator Request]
{
    "validator_language": "python",
    "validator_code": "import sys\n\nuser_output_file = sys.argv[1]\ntest_input_file = sys.argv[2]\n\nwith open(user_output_file, \"r\") as f:\n    user_output = f.read().strip()\n\nif user_output == \"hello\":\n    print(\"Accepted\")\nelse:\n    print(\"Wrong Answer\")",
    "user_output": "hello",
    "test_input": ""
}
\end{lstlisting}

\subsubsection*{Response Payload}
\begin{tabularx}{\textwidth}{|l|l|X|}
    \hline
    \textbf{Field} & \textbf{Type} & \textbf{Description} \\
    \hline
    `success` & boolean & `true` if the validator executed successfully. \\
    \hline
    `stdout` & string & The `stdout` of the validator (e.g., "Accepted"). \\
    \hline
    `stderr` & string & The `stderr` of the validator. \\
    \hline
    `err` & string & A high-level error message (e.g., "Validator Runtime Error"). \\
    \hline
\end{tabularx}

\paragraph{Example Response (Success):}

\subsubsection*{How to Interact with the API}

This section provides examples of how to interact with the `/api/execute` endpoint using various tools and programming languages.

\paragraph{Using cURL:}
\begin{lstlisting}[language=bash, caption=cURL Example]
curl -X POST -H "Content-Type: application/json" \
     -d "{\"language\": \"python\", \"code\": \"print('Hello from cURL!')\"}" \
http://127.0.0.1:5002/api/execute
\end{lstlisting}

\paragraph{Using Python `requests` library:}
\begin{lstlisting}[language=python, caption=Python Requests Example]
import requests
import json

url = "http://127.0.0.1:5000/api/execute"
headers = {"Content-Type": "application/json"}
payload = {
    "language": "python",
    "code": "print('Hello from Python requests!')"
}

response = requests.post(url, headers=headers, data=json.dumps(payload))
print(response.json())
\end{lstlisting}

\paragraph{Using JavaScript (Fetch API):}
\begin{lstlisting}[language=javascript, caption=JavaScript Fetch Example]
const url = "http://127.0.0.1:5000/api/execute";
const payload = {
    language: "python",
    code: "print('Hello from JavaScript Fetch!')"
};

fetch(url, {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify(payload)
})
.then(response => response.json())
.then(data => console.log(data))
.catch(error => console.error('Error:', error));
\end{lstlisting}

\paragraph{Using React with Axios:}
\begin{lstlisting}[language=javascript, caption=React with Axios Example]
import React, { useState } from 'react';
import axios from 'axios';

function CodeExecutor() {
    const [output, setOutput] = useState(null);

    const executeCode = async () => {
        const payload = {
            language: "python",
            code: "print('Hello from React with Axios!')"
        };
        try {
            const response = await axios.post('http://127.0.0.1:5000/api/execute', payload);
            setOutput(response.data);
        } catch (error) {
            console.error('Error executing code:', error);
            setOutput({ error: error.message });
        }
    };

    return (
        <div>
            <button onClick={executeCode}>Execute Code</button>
            {output && <pre>{JSON.stringify(output, null, 2)}</pre>}
        </div>
    );
}

export default CodeExecutor;
\end{lstlisting}

\begin{lstlisting}[language=javascript, caption=React without Axios Example]

    };

    return (
        <div>
            <button onClick={executeCode}>Execute Code</button>
            {output && <pre>{JSON.stringify(output, null, 2)}</pre>}
        </div>
    );
}

export default CodeExecutor;
\end{lstlisting}

\section*{How to Run}

\subsection*{1. Installation}
First, make sure you have Docker installed and running.

Then, install the required Python packages using pip:
\begin{lstlisting}[language=bash, caption=Installation Command]
# Make sure you are in the project root directory
# and you have activated your virtual environment

pip install -r requirements.txt
\end{lstlisting}

\subsection*{2. Running the Application}
To start the Flask application, run the following command:
\begin{lstlisting}[language=bash, caption=Run Application Command]
python app.py
\end{lstlisting}
The server will start on `http://127.0.0.1:5002`.

\section*{Core Python Files}

This section outlines the main Python files that constitute the Code Execution Engine project.

\subsection*{`app.py`}
This is the main Flask application file. It sets up the `/api/execute` endpoint, handles incoming JSON requests, extracts code execution parameters (`code`, `language`, `stdin`, `timelimit`, `memorylimit`), and then calls the `execute\_code` function from `execute.py`. It also configures CORS (Cross-Origin Resource Sharing) and returns the execution result as a JSON response.

\subsection*{`execute.py`}
This file contains the core logic for secure code execution within Docker containers. The `execute\_code` function performs the following key operations:
\begin{itemize}
    \item Validates the programming language provided.
    \item Checks for Docker availability and builds a `code-runner-image` if it doesn't exist.
    \item Uses temporary directories on the host to store user code and input files.
    \item Starts a Docker container in detached mode.
    \item Copies the code and input files into the container.
    \item Compiles C/C++ code if the language requires it.
    \item Executes the code within the Docker container, enforcing specified time and memory limits using `timeout` and `/usr/bin/time`.
    \item Parses the execution output, including standard output (`stdout`), standard error (`stderr`), time taken (`timetaken`), and memory consumed (`memorytaken`).
    \item Determines the success or failure of the execution, identifying issues like Time Limit Exceeded, Memory Limit Exceeded, Runtime Errors, or Compilation Errors.
    \item Ensures proper cleanup of the Docker container after execution.
\end{itemize}

\subsection*{`validate.py`}
This file contains the logic for validating a user's output against a custom validator script. The `validate\_output` function in this file is called by the `/api/validate` endpoint. It runs the validator script in a Docker container, passing the user's output and the original test input as arguments, and returns the verdict from the validator.

\subsection*{`run\_single\_test.py`}
This is a utility script primarily used for development and debugging. It allows developers to run a specific unit test (`test_fibonacci\_performance` from `TestCodeExecution` in `tests.test_execution`) without executing the entire test suite. It is not part of the application's core runtime.

\subsection*{`tests/test_api.py`}
This file contains integration tests for the Flask API. It uses the `unittest` framework to:
\begin{itemize}
    \item Start and stop the Flask development server as a background process before and after tests, respectively.
    \item Send POST requests to the `/api/execute` endpoint.
    \item Assert the HTTP status code and the content of the JSON responses.
    \item Cover various scenarios, including successful executions, compilation errors, and performance tests across different supported languages (Python, C, C++).
\end{itemize}

\subsection*{`tests/test_execution.py`}
This file contains unit tests for the `execute\_code` function, directly testing the core code execution logic without involving the Flask API. It uses the `unittest` framework and includes a `run\_test` helper function for detailed output. The tests cover a comprehensive range of scenarios, including:
\begin{itemize}
    \item Basic "Hello World" executions for Python, C, and C++.
    \item Handling of multi-line standard input.
    \item Time Limit Exceeded (TLE) scenarios for all supported languages.
    \item Memory Limit Exceeded (MLE) scenarios for all supported languages.
    \item Various Runtime Errors, such as division by zero and segmentation faults.
    \item Compilation Errors.
    \item Performance-related tests (e.g., Fibonacci sequence calculation).
\end{itemize}

\section*{Tests}

This directory contains the test suite for the Code Execution Engine. The tests are divided into two main categories:

\subsection*{1. Unit Tests}
\begin{itemize}
    \item \textbf{File:} `test\_execution.py`
    \item \textbf{Description:} These tests directly invoke the `execute\_code` function from `execute.py`. They are designed to verify the core logic of the code execution engine, including language support, resource limits, and error handling, without involving the Flask API.
    \item \textbf{How to Run:}
    \begin{lstlisting}[language=bash, caption=Run Unit Tests]
python -m unittest tests/test_execution.py
    \end{lstlisting}
\end{itemize}

\subsection*{2. API Tests}
\begin{itemize}
    \item \textbf{File:} `test\_api.py`
    \item \textbf{Description:} These tests interact with the Flask API endpoint (`/api/execute`). They verify the end-to-end functionality of the system, including the Flask application, request/response handling, and integration with the code execution engine. The API tests automatically start and stop the Flask development server.
    \item \textbf{How to Run:}
    \begin{lstlisting}[language=bash, caption=Run API Tests]
python -m unittest tests/test_api.py
    \end{lstlisting}
\end{itemize}
